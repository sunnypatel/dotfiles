Create CONTRIBUTING.md at repository root. This is a practical guide, not a community contribution document. Keep it concise and actionable.

Structure:

**Title:** Adding New Tools

**Overview:**
Each tool gets its own Stow package under `stow/`. The package directory structure mirrors where files should end up in `$HOME`. GNU Stow creates the symlinks.

**Step-by-step walkthrough using a concrete example (adding starship prompt):**

1. Create the package directory structure:
```
stow/starship/.config/starship.toml
```
This mirrors `~/.config/starship.toml` (the file's target location).

2. Add the config file with your desired settings.

3. Register the package in the Makefile:
   - Add package name to the `stow-packages` target (the `stow -R` command line)
   - If the tool needs Homebrew installation, add it to the `install-packages` loop with format `package:command` (e.g., `starship:starship`)

4. Test: `make stow-packages` to verify symlinks, then `ls -la ~/.config/starship.toml` to confirm.

**Package structure conventions:**
- XDG-compliant configs go under `stow/<tool>/.config/<tool>/`
- Home-directory dotfiles go under `stow/<tool>/.<filename>` (e.g., `stow/zsh/.zshenv`)
- One tool per package — never mix tools
- Package name matches the tool name

**Second example: tool with home-directory config (e.g., a .gemrc file):**
```
stow/ruby/.gemrc
```
This mirrors `~/.gemrc`.

**What NOT to add:**
- Language package managers (npm, cargo, pip) — see REMOVED.md
- GUI application configs — manage separately
- Secrets or tokens — use .gitignore

Keep total length under 80 lines. This is personal dotfiles documentation, not an open-source contribution guide. No PR process, no code review, no issue templates.
